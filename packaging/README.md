# Publishing GlassLedge to the Microsoft Store (MSIX)

GlassLedge ships two ways: the **Inno Setup installer** on GitHub Releases (`build\build-installer.ps1`) and an **MSIX package** for
the Microsoft Store (`build\build-msix.ps1`). They are built from the same code and the same version number.

| Folder | What it holds |
|---|---|
| `msix/AppxManifest.template.xml` | The package manifest; `build-msix.ps1` fills in the identity and version |
| `msix/store-identity.json` | The three values Partner Center gives you (paste them in once) |
| `msix/Assets/` | Package logos in every size Windows asks for (generated by `build/make-brand-assets.py`) |
| `store/art/` | Optional Store listing images: tile icon, box art, poster art, super hero art |

## First submission

1. **Reserve the name.** Partner Center > Apps and games > **New product** > **MSIX or PWA app** > reserve `GlassLedge`.
   (A name can't be reserved under two product types, so choose before you reserve.)
2. **Paste the identity.** In the product, open **Product management > Product identity** and copy `Package/Identity/Name`,
   `Package/Identity/Publisher` and `Package/Properties/PublisherDisplayName` into `msix/store-identity.json`.
3. **Try a local build.** From the repo root, in PowerShell with the Windows 10/11 SDK installed:

   ```powershell
   .\build\build-msix.ps1 -TestSign
   ```

   It prints the two commands to trust the test certificate and install the package. Then run the checklist below.
4. **Upload.** The file for the Store is the **unsigned** `artifacts\msix\GlassLedge-<version>.0-x64.msix` (the Store signs it).
   Never upload a file with `-DEV` or `test-signed` in its name.
5. **Fill in the listing, privacy URL, age rating and pricing** from the project's Store listing notes, then submit.

Every later release needs a higher version: change `<Version>` in `Directory.Build.props`, rebuild, upload as a new submission.
The package version is the app version plus `.0`; the Store reserves the last number.

## What to check in the packaged app

The package runs the same app, but Windows gives packaged apps a private view of AppData, so test these once:

- [ ] Launches; tray icon appears; **Add widget...** works; widgets keep their position after exiting and relaunching.
- [ ] **Old settings:** put a `settings.json` in `%APPDATA%\FloatingWindowOrganizer\` and launch the packaged app. Do the widgets come across?
  (This is the one thing I could not predict. If not, the Store version simply starts fresh.)
- [ ] **Start with Windows:** Settings > Apps > Startup lists GlassLedge (off by default) and turning it on works.
- [ ] **Win+D** (Show desktop) keeps the widgets.
- [ ] **Uninstall** from Settings removes the app and its tray icon.
- [ ] With the installer version also installed, launching the second copy does not duplicate widgets (single-instance guard).
